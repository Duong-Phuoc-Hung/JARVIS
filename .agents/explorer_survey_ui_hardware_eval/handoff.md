### 1.1 UI Overlay Architecture & Thread Isolation (`jarvis/ui/overlay.py`, `jarvis/core/app.py`)
- **Thread Lifecycle**: In `jarvis/ui/overlay.py:448-469`, `AlwaysOnOverlay.start()` spawns a dedicated background daemon thread:
  ```python
  self._thread = threading.Thread(
      target=self._run_tk,
      daemon=True,
      name="JARVIS-AlwaysOnOverlay",
  )
  self._thread.start()
  ```
- **Thread Marshaling Mechanism**: In `jarvis/ui/overlay.py:1820-1837`:
  ```python
  def _schedule(self, fn: Callable[[], None]) -> None:
      """Dispatches work safely to Tkinter event thread or runs immediately in headless mode."""
      if self._headless or not self._root:
          try:
              fn()
          except Exception as e:
              logger.debug("Headless execution error: %s", e)
          return

      try:
          self._root.after(0, fn)
      except Exception as e:
          logger.debug("Failed to schedule Tk action: %s", e)
          try:
              fn()
          except Exception:
              pass
  ```
  Every public UI mutation method (`show_listening`, `show_thinking`, `show_response`, `show`, `hide`, `update_task_dag`, `append_code_log`, `display_visual_result`, `toggle_sidebar`, `collapse_sidebar`, `expand_sidebar`, `minimize_to_arc_reactor`, `update_telemetry`, `update_audio_level`) routes exclusively through `self._schedule(callable)`.
- **Concurrency & State Synchronization**: Shared state buffers (`_history`, `_code_logs`, `_visual_results`, `_memory_facts`, `_waveform_bars`, `_current_dag`) are protected by `self._lock = threading.RLock()` (`overlay.py:312`).
- **Animation Timers**: Animation handles (`_breathing_job`, `_typing_job`, `_hide_job`, `_waveform_job`, `_telemetry_job`) execute via `self._root.after(ms, callback)` within Tkinter's event thread and are safely cancelled via `self._root.after_cancel(job)` in `_cancel_all_animations()` (`overlay.py:1805-1819`).
- **Verdict**: `AlwaysOnOverlay` is **100% thread-isolated**. External worker threads (audio capture, VAD, STT, LLM router, TTS, global hotkeys) never invoke Tkinter widget methods directly; all calls are non-blocking event dispatches (<0.05ms overhead), ensuring voice recording latency is completely isolated from GUI rendering.

## 3. Caveats
- **Headless CI vs Desktop GUI**: In headless CI environments (GitHub Actions / containerized tests), Tkinter and `pystray` gracefully fall back to headless mock mode. Unit tests must test both headless state mutations and mocked GUI handlers.
- **Action Name Aliasing**: In `jarvis/core/app.py`, the core action is registered as `system_status`, while legacy rule engine uses `hardware_status_query` and `hardware_telemetry_check`. `VALID_ACTIONS` in `routing_eval_n150.py` recognizes all three as valid aliases under `system_status`.
